# Janjua Curtain House

Premium marketing site and admin dashboard for **Janjua Curtain House** — custom curtains and
blinds in the UAE.

Next.js 16 (App Router) · TypeScript · Tailwind CSS v4 · Framer Motion · Supabase · Vercel-ready.

---

## Quick start

```bash
npm install
cp .env.example .env.local   # fill in your Supabase keys (optional at first)
npm run dev
```

Open http://localhost:3000.

**The site runs without Supabase.** Every data helper falls back to the content in
`src/lib/content.ts`, so you can design, review and deploy before the database exists. The admin
dashboard stays locked until Supabase credentials are present.

## Environment variables

| Variable | Where | Purpose |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | client + server | Supabase project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | client + server | Public anon key (always subject to RLS) |
| `SUPABASE_SERVICE_ROLE_KEY` | **server only** | Privileged maintenance key — never prefix with `NEXT_PUBLIC_` |
| `NEXT_PUBLIC_SITE_URL` | build | Canonical URL for metadata, sitemap and Open Graph |

The service-role key is only reachable through `src/lib/supabase/admin.ts`, which imports
`server-only` — importing it into a Client Component fails the build by design.

## Supabase setup

1. **Create the schema.** Supabase Dashboard → SQL Editor → paste `supabase/schema.sql` → Run.
   This creates the five tables, the enum, all RLS policies, and the public `gallery` storage
   bucket. It is safe to re-run.

2. **Seed the content.** Run `supabase/seed.sql` for the service list, the site settings row and
   the 20% promotion. It only inserts information the owner supplied.

3. **Create the admin user.** Authentication → Users → *Add user* → enter an email and password,
   and confirm the user.

   > **Important:** the `is_admin()` function treats *any confirmed authenticated user* as an
   > administrator. Turn **off** public sign-ups (Authentication → Sign In / Providers → disable
   > "Allow new users to sign up") so the only accounts are the ones you create by hand.

4. **Sign in** at `/admin/login`.

### Tables

| Table | Public read | Public write | Admin |
| --- | --- | --- | --- |
| `inquiries` | ✗ | insert only | full |
| `gallery` | ✓ | ✗ | full |
| `services` | active rows only | ✗ | full |
| `promotions` | active rows only | ✗ | full |
| `site_settings` | ✓ | ✗ | full |

Storage: the `gallery` bucket is world-readable; only authenticated admins can upload, update or
delete objects. Images live in Storage, and only the URL and path are stored in Postgres.

## Admin dashboard (`/admin`)

| Page | What it controls |
| --- | --- |
| Overview | Inquiry counts, gallery size, active services, the live promotion |
| Inquiries | Search, filter by status, open details, reply via WhatsApp/phone, change status, delete |
| Gallery | Upload to Storage with title, description, category and featured flag; delete (row + file) |
| Services | Create, edit, reorder, enable/disable and delete services |
| Promotions | Discount, headline, supporting text, CTA label, date window, activate/deactivate |
| Site Settings | Business name, tagline, phone, WhatsApp, location, email, social links |

`/admin` is excluded from `robots.txt` and carries `noindex`. `src/proxy.ts` redirects any
unauthenticated request to the login page before a dashboard page renders.

Activating a promotion automatically deactivates the others, so only one offer is ever live.

## Replacing the placeholder imagery

`public/images` currently holds **vector placeholders** generated by
`scripts/generate-placeholders.mjs` — brand-coloured stand-ins, not photographs.

To use real photos, drop files with the same names into the same folders (JPEG or WebP, roughly
3:2 for service cards and 4:5 for collections), or upload through the admin gallery. Nothing else
needs to change. To regenerate the placeholders after editing the script:

```bash
node scripts/generate-placeholders.mjs
```

`next.config.ts` enables `dangerouslyAllowSVG` with a `script-src 'none'; sandbox` CSP purely so
these in-repo vector files can pass through the image optimizer. Once every placeholder is
replaced with raster photography you can remove that option.

## Deploying to Vercel

1. Push the repository to GitHub and import it into Vercel.
2. Add the four environment variables above (Production and Preview).
3. Set `NEXT_PUBLIC_SITE_URL` to the real domain so metadata, the sitemap and OG tags resolve.
4. Deploy. No other configuration is required.

of experience, customer counts, awards, certifications, branch addresses, testimonials or social
accounts. Structured data (`HomeAndConstructionBusiness`) is limited to the business name,
telephone, country (`AE`) and services — no fabricated street address.
